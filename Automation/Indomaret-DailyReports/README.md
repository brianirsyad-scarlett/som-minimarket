# Indomaret Daily Reports — automated download

Downloads the **newest generated file** for 3 report types from Indomaret's DCP
portal, straight to the folders your existing extraction scripts already watch.

| reportTypeId | Report name | Destination |
|---|---|---|
| 2 | Daily Selling Out Performance by Branch and Product | `...\Indomaret\Sell Out` |
| 3 | Daily Selling Out & Stock by Store and Product | `...\Indomaret\Daily Sell Out` |
| 10 | Daily Stock by Branch and Product | `...\Indomaret\Stock` |

This is a **separate automation from `Indomaret-MarketShare`** because it hits a
different part of the API entirely: these are pre-generated report *files*
(a daily batch job on Indomaret's side builds a `.zip`), not a live Power BI
query. Same login, same account - just a different endpoint family. No browser
needed here either, same as Market Share - plain JSON API calls plus a plain
file download.

## How it works

1. Login + OTP (same as Market Share) → `accessToken`.
2. `GET .../report/search?reportTypeId=<id>&sort=id,desc&perPage=1` → the single
   newest generated report for that type (filename + a `downloadToken`).
3. `GET .../report/download/<downloadToken>` → a **pre-signed Google Cloud
   Storage URL, valid for only ~59 seconds**.
4. `GET <that signed URL>` (no auth needed) → the actual `.zip` bytes, saved
   under its original filename.

The `.zip` is saved as-is, not extracted — your existing `1_zip_converter.py` /
`2_folder_extractor.py` scripts in each destination folder already expect a raw
zip as their input (confirmed: the `Stock` folder had several unprocessed zips
sitting there from your own manual downloads when this was built).

If a file with that exact name already exists in the destination, it's skipped
(not re-downloaded) unless you pass `-Force`.

**Gap-filling**: each run checks the **5 most recent** reports per type (not just
the newest) and downloads any that aren't on disk. This matters because the task
runs once a day — if Indomaret's generation slips and two files appear between
runs, only looking at the newest would skip the middle one permanently. Adjust
the window with `--look-back N` if you ever need to reach further back.

## 1. Setup (once)

```powershell
cd "D:\SCARLETT_512\SCARLETT-329\SOM\Automation\Indomaret-DailyReports"
.\setup.ps1
```

## 2. Fill in `.env`

Same account as `Indomaret-MarketShare` — copy `INDOMARET_EMAIL` /
`INDOMARET_PASSWORD` / `INDOMARET_TOTP_SECRET` from that folder's `.env` if
you already filled it in.

## 3. Test it

```powershell
.\run.ps1
```

Downloads all 3. Or just one:

```powershell
.\run.ps1 -Report 10
```

Force a re-download even if the file's already there:

```powershell
.\run.ps1 -Report 3 -Force
```

## 4. Schedule it

```powershell
.\register_schedule.ps1
```

**Defaults to 16:00, not 00:00** — unlike Market Share, these files are
generated by Indomaret's own backend once a day, and the capture this was
built from showed each day's file appearing around 14:00–15:00 local time.
Scheduling at midnight would just re-fetch yesterday's file. Adjust if the
generation time drifts:

```powershell
.\register_schedule.ps1 -At 18:00
.\register_schedule.ps1 -Remove   # unregister
```

## Usage reference

```powershell
.\.venv\Scripts\python.exe indomaret_daily_reports.py --list
.\.venv\Scripts\python.exe indomaret_daily_reports.py --report all
.\.venv\Scripts\python.exe indomaret_daily_reports.py --report 2 --force
.\.venv\Scripts\python.exe indomaret_daily_reports.py --look-back 10   # reach further back
```

## Troubleshooting

`run.log` in this folder records every run.

| Message | Fix |
|---|---|
| `Login rejected` / `2FA rejected` | Same causes as Market Share - check `.env` |
| `No generated reports found for ... yet` | Not a failure - that report type has nothing generated yet for today |
| `HTTP ... downloading the file itself` | The signed URL likely expired (59s window) - rerun; if it keeps happening, the download-token step may need a closer-together retry |
